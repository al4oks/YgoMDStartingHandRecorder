# 使用说明（YGO 起手记录器）

> 配套文档：[设计文档](design.md) · [代码地图](code-map.md)
> 面向日常使用。主程序窗口标题「YGO 起手记录」，四个同级页签：**捕获 / 记录 / 卡组 / 存储**。

## 0. 启动与卡片数据

任选其一：

- 开发运行：`dotnet run --project src/YgoMDStartingHandRecorder`（可带参数 `[repoRoot]`；repo 内自带 `data/cards.json`，无需下载）。
- 调试 exe：`src\YgoMDStartingHandRecorder\bin\Debug\net11.0-windows10.0.19041.0\YgoMDStartingHandRecorder.exe`。
- **单文件便携**：`dotnet publish src/YgoMDStartingHandRecorder -c Release -p:PublishProfile=SingleFile` 产出的 `publish\YgoMDStartingHandRecorder.exe`（约 219MB）。可拷到任意目录双击运行，无需安装 .NET；**卡表不再内嵌**——首次启动若没有卡表会弹「缺少卡片数据」提示，点「下载」从百鸽数据源拉取（zip 约 2.4MB，解包后约 13.9MB，带官方 MD5 校验与进度条）；也可稍后到「存储」页下载。运行时在 exe 旁自动建 `records/`、`data/`（卡表+卡图缓存）、`captures/`。

启动后底部状态栏先显示「模型加载中…」，OCR 模型就绪后变「就绪：选择大师决斗窗口后点击「先手截图 / 后手截图」」。首次加载约数秒。**没有卡表时捕获按钮禁用**，状态栏提示去存储页下载；记录/卡组页仍可浏览（卡名显示为未识别/MISS）。

## 1. 捕获页

顶栏（左→右）：

| 控件 | 作用 |
|---|---|
| 窗口下拉框 | 列出当前可见窗口；默认预选 Master Duel / Yu-Gi-Oh / 游戏王 / `masterduel`。测试时可选自有 viewer 窗口 |
| **刷新窗口** | 重新枚举可见窗口（MD 后开/改标题时用） |
| 卡组下拉框 | 选择本局所用卡组（来自「卡组」页导入）。**选中/切换只预备会话名**（`卡组名_yyyyMMdd_HHmmss`），**到本次运行第一手真正入库时才写进数据库**——没截过图就不会留下空会话。影响：记录归类、上手率统计口径、**超框候选约束**。不选=**未分类：共用同一个「未分类」会话**（无时间戳、不另建），超框约束不启用 |
| **先手截图**（蓝） / **后手截图**（红） | 一步完成：截窗口客户区 → 识别 5 卡 → 存 PNG 到 `captures/` → **五张全部识别（或人工改正）后才入库**（带先后手+卡组）。两者仅先后手标记不同 |

**先后手与入库状态（P7 起）**：

- 启动时先后手徽章是**空白态「未定 / TURN」**（银白六边形），不预设先手；点了哪个截图按钮才定哪个。
- 表头/选项卡高亮用**银白纵向渐变**，蓝/红只表示先手/后手，不作其他装饰色。
- 有任一槽卡名不在卡表（未识别）时**本手不写入记录库**：出现琥珀色横幅「未入库 · N 张待纠正」+ 芯片「未入库」，状态栏也转琥珀。逐槽点「改」选定正确卡，**五张齐全的那一刻自动入库**（芯片转绿「已入库」），无需再点截图。
- 未入库期间的纠正只写 OcrAlias（下次同段坏 OCR 自动命中）；入库后纠正才写进该条记录。
- 上一手还没补齐就再点截图 = **放弃上一手**（状态栏会明说），只保留新截图。
- 未分类会话行显示 `未分类 · 本次第 N 局 · 不计累计`：先后手上手率累计**只对选了卡组的会话**有意义，未分类不算四率。

中部为**证据预览**（本次截图缩放显示）；下方**卡名栏**逐行显示 `序号 卡名 (sim x.xx)`，并附：

- `理论xx.x%`：该卡在本卡组的超几何理论上手率；
- `合xx.x%↑/↓/-`、`先…`、`后…`：本卡组**当前会话**累积实际上手率（合计/先手/后手），与理论差 ±1pp 内标 `-`，否则 ↑/↓；**含本次识别**；
- `（已纠正）`：该槽经人工改过。

逐槽纠正（卡名栏每行末的「改」按钮）：

| 按钮 | 作用 |
|---|---|
| **改**（每槽一个） | 对第 N 槽人工纠正：弹「选择卡名」对话框（弱匹配时预填 top-5 候选，可搜索全卡表）→ 确定后写 OcrAlias（下次同段坏 OCR 自动命中）+ 卡名栏标「（已纠正）」。本手已入库→同时写进该条记录；**本手尚未入库（有未识别槽）→只写 alias，五张补齐后自动入库** |

**悬浮窗（P16）**：捕获页工具栏「悬浮窗」按钮开/关一个**置顶小窗**（高度随内容自适应、无多余空白;默认屏幕左侧偏上、避开主窗标题栏关闭按钮，可拖标题栏移动、可切换置顶），只放 **先手/后手截图按钮 + 五张卡名 + 各卡合计上手率**（+当前卡组名）；置信度、理论、先/后手明细等都不在悬浮窗显示，需要时开主程序看。悬浮窗与主程序共用同一识别上下文，点悬浮窗按钮截图后两边结果同步更新；关主程序时悬浮窗一起关。

**「重识别」已移除（2026-11-16）**：捕获页与记录页的重识别按钮都撤了（实际用处不大）。识别不满意就**回 MD 重新截图**（像素被游戏内 overlay 遮挡时重识别本来也无效）；已入库记录要改卡名，用记录页详情的逐槽「改/候选」。

状态栏提示截图/识别/入库进度与结果（如「已保存并入库（先手·幕帘猫） …png」）。

常见提示：

- 「目标窗口已最小化，请先还原」：MD 最小化时不截黑图，还原后再点。
- 「截图失败：窗口可能最小化、独占全屏或不支持离屏渲染」：改用窗口化/边界全屏。
- 截图瞬间 MD 边框闪黄框 = Windows 对 WGC 抓屏的隐私指示，属正常、只读不注入。

## 2. 记录页

顶栏：会话下拉框（含「全部会话」；卡组会话＝一次运行×一个卡组，名为 `卡组名_时间戳`，**首次入库时自动创建**、暂不支持改名；**「未分类」是共用的一个会话**，不带时间戳。**没有记录的会话不会出现在库里**，旧版遗留的 `未分类_时间戳` 空会话/按次会话在开库时自动折叠合并，迁移前同日备份到 `records/backup-session-scheme-yyyyMMdd/`）+ 卡组过滤下拉框（全部卡组/未分类/各卡组）。**两个下拉有约束：选了卡组后，会话下拉只列含该卡组记录的会话**（选「未分类」就只列未分类的会话；「全部卡组」=全部会话）。

按钮行（左→右）：刷新 / 错误识别映射 / 清理记录 / 清理截图；**行最右**：导入记录集 / 导出记录集（开发版与发布版都有）。

| 按钮 | 作用 |
|---|---|
| **刷新** | 重读库、重建列表与过滤项 |
| **清理记录** | 删除**勾选**的记录（没勾选则删当前选中行），**证据截图一并删除**，单次确认 |
| **清理截图** | 清空截图缓存目录（`captures/` 或 `YGO_AUTOSAVE`）。两段确认：首点显示将删张数/大小并变「确认清理截图?」，再点执行，点「刷新」取消。记录保留并标「证据截图已被清理」;不触碰导入记录集的样本图 |
| **导出记录集** | 把当前过滤结果导出 CSV（含卡名/先后手/卡组/耗时等，UTF-8 BOM） |
| **导入记录集** | 把一个已标注样本目录（文件名带 `__名字+…`）导入为一条会话，供回归/验收 |
| **错误识别映射** | 打开 OCR 原文→卡名 的人工确认映射管理（原「别名管理」） |

主列表列：`勾选框 / Id / 时间（含日期 yyyy-MM-dd HH:mm:ss） / 会话 / 手牌缩略×5 / 先后 / 纠错 / 耗时ms`。**会话列宽随窗口自适应**（放大窗口时变宽，不再固定窄列）；**纠错列只写「纠错」，有纠正的行打勾 ✓**。**切到本页默认选中首行并立即加载详情**。状态栏显示 `共 N 条记录 · 截图缓存 X 张 / Y MB`（缓存目录占用，清理后归零）。

右侧详情 pane：

- 证据图（本次截图；若已清理显示占位「证据截图已被清理」，文件缺失显示「证据截图缺失：路径」）；
- 5 槽行：`序号 卡名（已纠正）` + `raw=OCR原文 sim=匹配度` + **改/候选** 按钮（同捕获页逐槽改，弹卡名选择）。
- **不再提供先后手/卡组修改下拉**：先后手与卡组归属在捕获时就定好；要改归属请重新捕获或清理后重录。

**错误识别映射**对话框：列出 `OCR原文 → 卡名 (hits N)`；**删除选中** 移除某条映射；**关闭** 退出。hits 为该映射被识别命中次数，可佐证闭环生效。

**选择卡名**对话框（改N/改候选共用）：顶部搜索框 + 候选列表（弱匹配预填 top-5，带 sim）；输入即搜全卡表；**确定** 提交、**取消** 放弃。模态对话框请人工点选（不做自动化）。

## 3. 卡组页

**一级（卡组 tiles）**：一行 **4 个**切角卡片（封面 + 张数角标 + 名称 + 构成/样本/导入时间），末位是虚线「导入新卡组」tile。**封面在建卡组时从主卡组随机抽一张并写库，之后固定不变**（旧库没有封面字段时开库自动补抽一次）；点卡片进二级。顶栏：导入卡组 / 刷新。

**二级（卡组详情）**：顶栏 ← 返回 / 卡组名与构成 / **上手率口径下拉** / 样本局数（先/后）/ 删除卡组 / 刷新。

口径下拉：`全部会话合并`（默认，把该卡组所有会话的记录合并统计）或某个具体会话（`卡组名_时间戳`，只统计那一次运行）。只列出含该卡组记录的会话；切换即重算下方卡格。

卡格**一行 10 张**（缩略图比例；主卡组与额外卡组各一块），每格：卡图 + ×N 投入角标 + 卡名 + 四行数据：

- **理论**＝超几何起手率（只主卡组）；
- **合 / 先 / 后**＝当前口径下 `上手次数/局数` + 实际上手率（如 `合 2/3 66.7%`）；**不再画 ↑↓- 箭头，改用数字颜色**：绿=高于理论、红=低于理论、灰=持平(±1pp)或无样本；某桶 0 局显示 `0/0 -`；
- 额外卡组不计上手率（四行恒 `—`）；未命中卡表的卡名标红（MISS）。

图例行说明：×N = 投入张数；理论 = 超几何起手率；合/先/后 = 上手次数/局数 与实际上手率；数字颜色 绿高于理论 / 红低于理论 / 灰持平或无样本。

**类型统计（P13/P14，原「属性聚合」）**：详情顶部「类型统计」区给卡牌打类型标签（动点/手坑/废件/解牌…或自定义）：

0. **新建卡组自带示例**：类型「动点 / 手坑 / 废件」+ 组合类型「两卡动」（空内容，帮助理解这两行用途），**都可以删**。
1. 输入新类型名 → **添加类型**（如「手坑」）。
2. **点类型名进入编辑态**（出现「退出编辑」按钮与提示）→ **连点卡牌**加入/移除（再点同一张=移除）→ **再点该类型名或「退出编辑」结束**。编辑态下被标注卡格金边高亮+类型小标。
3. 类型 chip 显示：**X种/Y张**（种数/投入张数）、**理论（超几何≥1）**、**合计上手率**、**平均每回合上手张数**（实际均值，含同卡多 copies）。
4. **详情**弹窗：上手 **0~5 张分布**（合/先/后 各 k 张局数+占比）+ 合/先/后 上手率 + **实际平均每局上手张数** + 理论两种口径（超几何≥1 与期望张数）。
5. chip 的 **删** 删除类型（含其标注）。

**组合统计（P13/P14，原「组合聚合」）**：「组合统计」区管理组合类型（如「两卡动」），创建方式与类型统一——**面板输入名字→添加组合类型→点类型名进入编辑（管理弹窗）**：

- 新建卡组自带空的「两卡动」类型;管理弹窗左侧类型列表（**选中高亮**）可增删/切换;右侧条目编辑：**必需卡**勾选（每卡各≥1 全齐）+ **可选卡**勾选（其中任意≥1;不勾=纯全齐条目）→ **添加条目**。即支持「一张卡 + 集合中任意一张」的组合。
- 判定：**条目成立 = 必需卡全齐 且（可选集合空 或 其中任意≥1）**；**类型上手 = 任一条目成立**。
- 类型 chip 显示 条目数、**理论上手率**（精确多元超几何+条目容斥）、合计上手率;**详情** = 类型汇总+理论 + 逐条目（卡名清单含「任选[…]」+ 理论 + 合/先/后 率）。
- 类型与组合都**按卡组独立**存记录库;删卡组级联清理;口径下拉（合并/单会话）同样作用。

## 4. 存储页

- **默认路径（P17）**：两个目录默认在**系统文档** `Documents\YgoHand\captures` 与 `Documents\YgoHand\carddata`（repo 内开发且已有 data/cards.json 时卡表回退 repo/data）;可用「更改路径」改到任意空目录（整体搬迁）。
- **卡片数据（卡表 + 卡图缓存）**：显示目录、合计占用、卡表张数、**更新时间**、MD5;**清理卡图缓存**按钮两段确认后只删 cardimg（卡表保留，卡图按需重下）。
  - **更新卡表**：从百鸽 `ygocdb.com/api/v0` 重新下载 `cards.zip`（约 2.4MB）→ 解包 `cards.json` → 官方 MD5 校验 → 落盘并**记录更新时间**；下方进度条显示下载百分比。下载完成后识别器自动热重载，无需重启。
  - **更改路径**：选一个空目录，现有卡表+卡图缓存整体搬迁（跨盘符自动拷贝+删源），写入 `settings.json`。
  - 卡图仍按需从 CDN 下载缩略图到该目录 `cardimg/`，不 bulk 下载原图。
- **起手截图**：显示目录与占用（张数/MB）；**更改路径**同样整体搬迁现有截图;**清理截图**按钮两段确认后清空目录并把记录标记「证据截图已被清理」（与记录页同语义）。捕获页自动存盘、「记录」页清理截图都作用于该目录。
- 缺卡表时本页顶部琥珀横幅提示下载；设置落在 root（或 exe 目录）的 `settings.json`，环境变量 `YGO_AUTOSAVE` / `YGO_CARD_DATA` 优先（自动化隔离用）。

## 5. 标注工具（Ygo.Labeler，开发/验收用）

`dotnet run --project src/Ygo.Labeler -- [repoRoot] [imagesDir]`。

- 浏览目录 → 左侧样本列表；中部大图（可缩放/手牌区放大/1:1/拖移）。
- 底部 5 个槽输入框 + **共享向上弹出候选列表**：输入即搜卡表，焦点留在输入框，鼠标点击或 Enter 选中才提交；候选只显示规范名（重名才加 [id]）。
- **Enter = 保存并下一张**：把文件改名为 `{stem}__{name1}+…+{name5}.ext` 并更新 `labels.json`；**Skip** = 加 `SKIP_` 前缀跳过；未知槽填 `?`。
- 支持粘贴整行自动拆分到 5 槽。

见 [设计文档 §13](design.md#13-环境-knobs)。常用：`YGO_DB`（隔离记录库）、`YGO_DECK`（预选卡组）、`YGO_AUTOSAVE`（截图目录 override）、`YGO_CARD_DATA`（卡片数据目录 override）、`YGO_CAPTURE=wgc|pw`（强制捕获路径）、`YGO_DEBUGSHOT`（落盘排查）。

## 8. 常见问题

- **超框卡（如 黑之魔导的帘布）识别不稳**：在捕获页选对卡组再截；仍错就用 改N 点选一次（写 alias 后自动闭环）。
- **某局整手识别错**：多为截图时机被游戏内 overlay 遮挡 → 回 MD 重截。
- **闪卡 sim 逐帧波动**：火花动画所致，名字通常仍对；想要更稳一帧就回 MD 重截（重识别已移除）。
- **首次启动慢**：OCR 模型加载/单文件自解压原生库，属正常。
- **清理截图后还能看证据吗**：证据像素已删，详情区显示「证据截图已被清理」；记录的卡名/纠正/上手率统计保留，仍可逐槽「改/候选」。需要证据请回 MD 重截。
